# 空转会烧钱：当前 skill 如何避免无效重试

空转不是“模型慢”，而是模型在一个分块上反复调用工具、反复让模型自己重写，却没有任何实际进展。对商用 API 来说，每一次重试都是真金白银。

当前 skill 用四道闸门把这种循环截断。

## 1. 只把“文件真的改了 + check”算一轮

`check --chunk` 会记录每个分块的：

- 文件是否变了；
- 当前问题数；
- 真实修改轮次；
- 连续空检查次数。

模型只读文件、只跑 `check`、用 Python/sed 空改，都不算一轮。

## 1b. 大片英文不算“翻完”

中文里夹人名、术语、邮箱、URL 是正常的；把整段源文短语原样留在译文里不是。
`check` 会找译文中与原文逐字相同的英文词组（≥20 字符、两个以上小写词），报
`untranslated source text`，只点名那几个词，不要求重写整段。

普通句子也不能靠 `@@@VERBATIM@@@` 跳过：只要原文是散文，`check` 会报
`@@@VERBATIM@@@ on a prose segment`。代码、命令、日志、URL 不受影响。

这两类问题**不能登记人工介入**，必须继续翻译；这样“大片没翻”不会变成一条人工
记录悄悄混过去。它们也不计入 `translated` 进度，`next` 会继续把它当作 `repair`
返回。

## 2. 空检查会停，但不给兜底

文件没变就重复 `check`：

- 第一次：提示“先改点名的段，再检查”；
- 连续第二次：标记停止，不自动兜底，交主会话处理。

这样模型不能靠“反复 check”拖时间，也不能一次不改就吃到兜底。

## 3. 真改了但没进展，才自动兜底

文件真的变了，但问题数没有下降：

- 标记 exhausted；
- 只剩占位符错误时，`check` 自动做一次单标记补位；
- 补位失败，才进入人工介入。

兜底是本地操作，不调用模型，不产生 token 费用。

## 4. 到 6 轮就停

真实“修改 + check”最多 6 轮。到限后：

- 自动兜底一次；
- 还不过，`review --add` 登记；
- `next` 不再把这个块派给子代理。

人工介入只接受占位符类问题。未翻译、半成品、结构错误会被拒绝，必须继续翻译。被登记的块不计入 translated 进度，登记不再看起来像“完成”。

## 子代理被强杀时

如果客户端给子代理设了 `steps`，到限会强制结束。主会话随后运行：

```bash
epubzh check --config book.toml <stem> --chunk <n> --abandon
```

它会直接标记 exhausted、做一次兜底，并提示下一步是登记还是补译，不再重新数 6 轮。

`steps` 是可选配置，建议 25–30。skill 优先派 `translate`，用户没配时自动退回 `general`，不配置也能用，只是没有硬止损。

## 效果

| 情况 | 以前 | 现在 |
| --- | --- | --- |
| 反复 check 不改文件 | 可以一直刷 | 第二次就停 |
| 改了但没进展 | 继续让模型重试 | 自动兜底一次 |
| 6 轮还不行 | 靠模型自觉登记 | 工具提示登记并停止派发 |
| 子代理被强杀 | 主会话重新数 6 轮 | `--abandon` 直接收尾 |
| 登记未翻译内容 | 可以绕过 | 直接拒绝 |

一句话：**把“什么时候停、什么时候兜底、什么时候登记”从模型手里拿走，交给 `check` 的状态记录。** 模型只负责改，系统负责止损。
